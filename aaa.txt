# API Documentation for File Upload and Processing

## 1. File Upload

### Endpoint Description
This endpoint is used for uploading files of specified types (pptx, docx, pdf). After receiving the file, the backend will perform an initial validation, store it, and return a unique file ID for subsequent operations.

- **URL:** `/api/v1/upload`
- **Method:** `POST`
- **Content-Type:** `multipart/form-data`

### Request Parameters

| Parameter | Type   | Required | Description                                    |
|-----------|--------|----------|------------------------------------------------|
| `file`    | File   | Yes      | The file object selected by the user.          |
| `fileType`| string | Yes      | The file extension, e.g., "pdf", "docx", "pptx". |
| `fileName`| string | Yes      | The original name of the file.                 |

### Success Response

- **Status Code:** `200 OK`
- **Body:**
  ```json
  {
    "code": 200,
    "message": "Upload successful",
    "data": {
      "fileId": "u-1668688888",
      "fileName": "MyDocument.docx",
      "fileType": "docx",
      "fileSize": 123456,
      "uploadTime": "2023-10-27T10:00:00Z",
      "status": "processing"
    }
  }
  ```

### Error Responses

- **Status Code:** `400 Bad Request` (e.g., unsupported file type)
  ```json
  {
    "code": 400,
    "message": "Unsupported file type. Only pptx, docx, and pdf formats are allowed.",
    "data": null
  }
  ```
- **Status Code:** `413 Payload Too Large` (e.g., file size exceeds limit)
  ```json
  {
    "code": 413,
    "message": "File size exceeds the limit (e.g., 100MB).",
    "data": null
  }
  ```
- **Status Code:** `500 Internal Server Error`
    ```json
    {
      "code": 500,
      "message": "Server failed to process the request. Please try again later.",
      "data": null
    }
    ```

## 2. Query File Processing Status

### Endpoint Description
After uploading a file, the frontend can poll this endpoint to check the processing status of the file.

- **URL:** `/api/v1/upload/{fileId}/status`
- **Method:** `GET`

### URL Parameters

| Parameter | Type   | Description                               |
|-----------|--------|-------------------------------------------|
| `fileId`  | string | The unique ID returned after a successful file upload. |

### Success Response

- **Status Code:** `200 OK`
- **Body:**
  ```json
  {
    "code": 200,
    "message": "Query successful",
    "data": {
      "fileId": "u-1668688888",
      "status": "completed", // "processing", "completed", "failed"
      "progress": 100, // (0-100)
      "result": {
          "processedContent": "Content after processing...",
          "extractedText": "Extracted text...",
          "metadata": {
              "author": "John Doe",
              "pages": 10
          }
      },
      "error": null // This will contain an error message if processing failed
    }
  }
  ```
  *When `status` is `failed`:*
  ```json
  {
    "code": 200,
    "message": "Query successful",
    "data": {
      "fileId": "u-1668688888",
      "status": "failed",
      "progress": 50,
      "result": null,
      "error": "Failed to parse file content, format is incorrect."
    }
  }
  ```

### Error Response

- **Status Code:** `404 Not Found`
  ```json
  {
    "code": 404,
    "message": "File with the specified fileId was not found.",
    "data": null
  }
  ```
